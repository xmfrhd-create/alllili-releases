## 1. 한 줄 정의

**"Where to dance Latin, in any city, any week."**
전 세계 어느 도시든 살사 · 바차타 · 키좀바 · 주크 소셜, 페스티벌, 수업을 도시와 기간으로 바로 찾는 영어 웹사이트.

## 2. 문제 정의와 기회

| 문제 | 근거 |
|:--|:--|
| 기존 앱은 많지만 대부분 데이터가 비었거나 관리가 끊김 | 사용자 직접 사용 경험. BachataMap이 그나마 낫지만 유럽 중심이고 바차타 전용 |
| 내 도시와 여행 갈 도시 외에는 볼 필요가 없는데, 기존 서비스는 전 세계 목록을 늘어놓음 | 지역 맞춤이 핵심 결핍 |
| 범용 AI(ChatGPT 등)에 물어보면 "이 도시 소셜"을 꽤 잘 찾아줌 | 2026년 아프리카 여행 중 실제 사용 경험. 다만 링크 정확도가 떨어지고, 매번 새로 물어야 함 |

**기회**: 범용 AI가 대화할 때마다 하는 조사를 **미리, 모든 도시에 대해, 정기적으로** 해서 검색 가능한 페이지로 쌓아 두면, 그 페이지 자체가 구글 검색 유입(SEO)의 원천이 됩니다.

## 3. 범용 AI 대비 존재 이유 (가장 먼저 답해야 할 질문)

"ChatGPT가 이미 알려주는데 왜 Latinworld에 오는가?"에 대한 답입니다.

| 범용 AI | Latinworld |
|:--|:--|
| 매번 처음부터 검색, 답이 매번 다름 | 한 번 조사한 결과를 저장하고 검증해서 누적 |
| 날짜 개념이 약함 ("매주 화요일"인지 "이번 화요일"인지 불명확) | 반복 일정을 구조화해서 **이번 주 캘린더**로 보여줌 |
| 출처 링크가 틀리거나 오래된 경우가 많음 | 출처 링크 필수, 링크 생존 자동 확인, "마지막 확인일" 표시 |
| 리뷰, 상단 노출, 주최자 소통 없음 | 리뷰, 주최자 Claim, 문의 기능 |
| 구글 검색에 안 잡힘 | "salsa seoul", "bachata lisbon this week" 검색에 잡히는 페이지 |

결론: **AI는 수집 엔진이고, 상품은 "검증되고 날짜가 맞는 도시별 페이지"입니다.**

## 4. 대상 장르와 데이터 종류

장르: Salsa (On1, On2, Cuban 포함), Bachata (Sensual, Dominican), Kizomba (Urban Kiz 포함), Zouk (Brazilian Zouk).

| 데이터 종류 | 설명 | 비중 (예상) | 갱신 난이도 |
|:--|:--|:--:|:--|
| Recurring Social (정기 소셜) | "매주 목요일 21시, ○○바, 살사 60 / 바차타 40" | 약 60% | 낮음. 잘 안 바뀜 |
| Festival · Congress | 연 1회, 공식 웹사이트 있음 | 약 10% | 낮음. 웹사이트가 명확 |
| One-off Event (단발 파티, 워크숍) | 주로 인스타 · 페북에만 공지 | 약 15% | **높음. AI 수집 정확도가 가장 낮은 영역** |
| School · Class (학원, 정규반) | 웹사이트, 구글 지도 등록 많음 | 약 10% | 낮음 |
| Private Instructor (개인 레슨 강사) | 프로 댄서 본인 등록 위주 | 약 5% | 본인 등록 의존 |

**설계 핵심**: 소셜을 "이벤트"가 아니라 **"장소 + 반복 규칙"**으로 저장합니다. 그러면 한 번 수집해서 매주 캘린더를 자동 생성할 수 있고, AI 수집 비용과 오류가 크게 줄어듭니다.

## 5. 핵심 UX: 도시 우선

```
첫 방문
 └ 위치 자동 감지 (IP 기반, 허락 시 GPS) → "Dancing in Seoul this week"
     ├ Tonight / This weekend / This week 탭
     ├ 장르 필터 칩: Salsa · Bachata · Kizomba · Zouk
     └ 지도 보기

상단 고정 영역: "My Cities"
 ├ 현재 도시 (자동)
 └ 여행 예정 도시 + 날짜 (예: Barcelona, Mar 3~9) → 그 기간 일정만 보여줌

도시 페이지 (/city/barcelona)
 ├ 이번 주 소셜 캘린더
 ├ 다가오는 페스티벌
 ├ 학원 · 수업 · 개인 레슨
 ├ Travel Tips (치안, 비자, 결제 특이사항)
 └ 리뷰
```

* 로그인 없이도 전부 볼 수 있어야 합니다 (SEO와 첫 방문자 이탈 방지).
* 로그인하면 My Cities, 저장, 리뷰, 맞춤 추천이 활성화됩니다.

## 7. AI 데이터 파이프라인 (핵심 엔진)

### 7.1 흐름

```
① 도시 목록 (Seed)
   → ② 도시 × 장르별 AI 조사 (LLM + 웹 검색)
   → ③ 구조화 추출 (JSON: 이름, 장소, 주소, 요일 · 시간, 장르 비율, 가격, 출처 URL)
   → ④ 검증 (출처 URL 접속 확인, 주소 → 좌표 변환, 중복 제거)
   → ⑤ 신뢰도 점수 부여 → 기준 이상이면 자동 공개, 미만이면 검토 대기
   → ⑥ 정기 재검증 (갱신 주기는 도시 등급별)
```

### 7.2 도시 등급과 갱신 주기

| 등급 | 기준 | 도시 수 (예상) | 재조사 주기 |
|:--|:--|--:|:--|
| Tier 1 | 라틴 씬이 큰 도시 (서울, 바르셀로나, 뉴욕, 리스본, 카리 등) | 약 150 | 매주 |
| Tier 2 | 인구 50만 이상 또는 씬이 확인된 도시 | 약 1,000 | 매월 |
| Tier 3 | 그 외 씬이 확인된 도시 | 약 2,000 | 분기마다 |
| 승급 | 사용자 검색 · 조회가 많은 도시는 자동으로 상위 등급으로 올림 | | |

### 7.3 정확도 규칙 (환각 방지)

* **출처 URL 없는 항목은 저장하지 않습니다.**
* 출처 페이지를 실제로 열어서 이름 · 요일이 일치하는지 2차 확인합니다.
* 모든 카드에 "Last verified: 2026년 11월 20일", "Source: Instagram / Website" 표시.
* 사용자 버튼: "This is outdated" → 해당 항목을 즉시 재조사 대기열로.
* 주최자 Claim 후에는 주최자 입력이 AI 데이터보다 우선합니다.
* 인스타 게시물을 긁지 않습니다. 검색 결과에 나온 **인스타 계정 링크만 출처로 연결**합니다 (이미지 · 캡션 복제 없음 → 저작권 · 약관 리스크 최소화).

### 7.4 비용 추정 (월간, 가정 기반)

| 항목 | 계산 | 월 비용 (추정) |
|:--|:--|--:|
| Tier 1 | 150개 도시 × 4장르 × 주 1회 × 약 4.3주 ≈ 2,600회 조사 | |
| Tier 2 | 1,000 × 4 × 월 1회 = 4,000회 | |
| Tier 3 | 2,000 × 4 ÷ 3 ≈ 2,700회 | |
| 합계 | 약 9,300회 조사, 조사 1회당 웹 검색 약 3회 + 토큰 | **약 300~800달러** |

* 가정: 웹 검색 1,000회당 약 10달러, 조사 1회당 LLM 토큰 비용 약 0.02~0.06달러. 실제 단가는 개발 시점에 확인해서 다시 계산해야 합니다.
* **초기 비용 절감**: 첫 달에 전 도시를 1회 전수 조사(1회성 비용)하고, 이후에는 Tier 1만 매주 돌리면 월 100~250달러 수준까지 낮출 수 있습니다.

## 8. SEO 전략 (트래픽의 주 원천)

| 요소 | 내용 |
|:--|:--|
| URL 구조 | `/city/seoul`, `/city/seoul/salsa`, `/city/seoul/bachata/this-week`, `/festivals/2027`, `/festivals/kizomba` |
| 페이지 수 | 약 3,000개 도시 × (전체 + 4장르) ≈ 15,000페이지 + 개별 이벤트 · 학원 페이지 |
| 구조화 데이터 | schema.org `Event`, `DanceEvent`, `LocalBusiness` 마크업 → 구글 이벤트 검색 결과에 노출 |
| 렌더링 | Next.js ISR(정적 생성 + 주기적 재생성) → 빠르고 크롤링이 쉬움 |
| 사이트맵 | 도시 · 이벤트 단위로 자동 생성 |

**리스크 (중요)**: 구글은 2024년 3월부터 "대량으로 찍어낸 저품질 콘텐츠(scaled content abuse)"를 순위 하락 대상으로 명시하고 있습니다. 데이터가 없는 도시 페이지를 수천 개 만들면 **사이트 전체가 불이익**을 받을 수 있습니다.
대응: **실제 항목이 3개 이상인 도시 페이지만 검색엔진에 노출**하고(나머지는 `noindex`), AI가 쓴 일반론 소개 문단은 넣지 않습니다. 페이지의 가치는 글이 아니라 데이터여야 합니다.

## 10. 리뷰, 채팅

* 리뷰: 별점 1~5 + 한마디 (140자) + 태그 (Music, Floor, Level, Vibe, Value). 주최자 답글 가능.
* 채팅: MVP에서는 "Contact organizer" (주최자의 인스타 DM 링크 또는 이메일 폼). 자체 1:1 채팅과 그룹챗은 사용자 확보 이후 Stream 같은 SaaS로 구현.

## 11. 수익 모델과 월 200만 원 도달 계산

환율 가정: 1달러 ≈ 1,400원 → 목표 약 1,400달러.

| 수익원 | 계산 | 월 수익 |
|:--|:--|--:|
| 디스플레이 광고 (AdSense) | 월 30만 페이지뷰 × RPM 3~6달러 | 900~1,800달러 |
| 유료 상단 노출 (Featured) | 도시 타깃 상단 고정, 월 29달러 × 20곳 | 580달러 |
| 페스티벌 스폰서 배너 | 월 100~300달러 × 2곳 | 200~600달러 |

* **현실 점검**: 월 30만 페이지뷰는 SEO만으로는 보통 **6~12개월 이상** 걸립니다. 초기에 확실한 돈은 광고보다 **상단 노출 직접 판매**입니다. 페스티벌 주최자는 원래 해외 홍보비를 쓰는 고객입니다.
* AdSense는 승인 심사가 있습니다. 콘텐츠가 어느 정도 쌓인 뒤 신청해야 통과 확률이 높습니다.
* "개인화 광고": 상단 노출을 **사용자의 현재 도시 · 여행 예정 도시 · 장르**에 맞춰 보여주는 방식으로 구현합니다. 광고주 입장에서 단가를 높게 받을 수 있는 근거가 됩니다.
* 3단계: 티켓 · 레슨 예약 결제 수수료 (5~10%), 온라인 수업 수수료.

## 13. 경쟁 현황 (v0.1 판단 수정)

v0.1의 "레드오션"은 **앱 개수 기준**이었습니다. 사용자 경험대로 실제로 데이터가 채워져 있고 관리되는 곳은 드물기 때문에, 이 시장은 **"기능 경쟁"이 아니라 "데이터 커버리지 경쟁"**이고 그 자리는 비어 있다고 봅니다. 단, 각 앱의 실제 데이터 품질을 제가 직접 검증하지는 않았습니다.

| 서비스 | 현황 | Latinworld 대비 |
|:--|:--|:--|
| BachataMap | 바차타 전용, 유럽 중심 | 장르 · 지역 커버리지에서 우위 가능 |
| go&dance | 스페인 중심 | 동일 |
| Salsa Vida | 페스티벌 DB 위주 | 로컬 소셜에서 우위 가능 |
| 기타 앱 10개 이상 | 데이터 빈약, 업데이트 불규칙 (사용자 관찰) | |
| **ChatGPT, Gemini 등 범용 AI** | **실질적 최대 경쟁자** | 3장 참고. 구조화 · 검증 · 날짜 · SEO로 차별화 |
