# 라틴오브더라틴 (Latin of the Latin) PRD v0.1

작성일: 2026년 11월 24일 · 상태: 초안 (검토 필요)

## 1. 한 줄 정의

전 세계 살사 · 바차타 · 키좀바 · 주크 이벤트와 수업을 **장소와 기간으로 한 번에 찾는 곳**, 그리고 나중에는 예약 · 결제 · 온라인 수업까지 되는 **라틴댄스계의 밋업**.

## 2. 문제 정의

| 문제 | 현재 상황 | 결과 |
|:--|:--|:--|
| 정보가 흩어져 있음 | 인스타 스토리, 카톡 오픈채팅, 네이버 카페, 페이스북 이벤트에 분산 | 현지인도 모름 (한국인인데 한국 이벤트도 모름) |
| 여행자 진입장벽 | 언어, 현지 커뮤니티 미가입, 스토리는 24시간 후 사라짐 | 여행 중 춤출 기회를 놓침 |
| 신뢰 정보 부재 | 이벤트 후기, 수준, 분위기, 치안, 결제 방식 정보가 없음 | 처음 가는 곳은 실패 위험이 큼 |
| 주최자 홍보 비용 | 매번 인스타 게시물, DM 응대 | 같은 질문 반복 (가격, 장소, 수준) |

## 3. 타깃 사용자

| 페르소나 | 설명 | 핵심 니즈 |
|:--|:--|:--|
| 여행하는 소셜 댄서 | 출장 · 여행지에서 춤추고 싶은 중급 이상 댄서 | "이번 주 리스본에서 바차타 소셜 어디?" |
| 로컬 댄서 | 자기 도시 이벤트를 다 못 챙기는 사람 | 주간 캘린더, 맞춤 추천 |
| 입문자 | 학원 · 수업을 찾는 사람 | 학원 비교, 리뷰, 체험 수업 |
| 프로 댄서 (강사) | 개인 레슨, 워크숍으로 수익을 내는 사람 | 노출, 예약, 인스타 연결 |
| 주최자 | 소셜, 페스티벌, 학원 운영자 | 홍보, 참가자 관리, 문의 응대 감소 |

## 4. 회원 체계

로그인은 **Google OAuth** 단일로 시작합니다 (iOS 앱 출시 시 Apple 로그인 추가 필수, 아래 리스크 참고).

| 권한 | 일반 댄서 | 프로 댄서 | 주최자 |
|:--|:--:|:--:|:--:|
| 이벤트 · 수업 검색, 저장, 리뷰 | ✅ | ✅ | ✅ |
| 채팅 (담당자 문의) | ✅ | ✅ | ✅ |
| 개인 레슨 등록 | ❌ | ✅ | ✅ |
| 인스타 계정 연결 (프로필 노출) | ❌ | ✅ | ✅ |
| 이벤트 등록 (소셜, 페스티벌, 워크숍) | ❌ | ❌ | ✅ |
| 학원 · 정규 수업 등록 | ❌ | ❌ | ✅ |
| 추가 인증 | 없음 | 인스타 계정 소유 인증 + 활동 증빙 | 인스타 · 웹사이트 소유 인증 + 연락처 인증 + 관리자 승인 |

**인증 방법 (제안)**
* 인스타 소유 인증: Instagram 로그인 연동 (Instagram API with Instagram Login, 비즈니스 · 크리에이터 계정 대상) 또는 "프로필 소개에 인증 코드 넣기" 방식
* 주최자: 위 + 휴대폰 인증 + 수동 승인. 첫 이벤트는 검수 후 공개
* 한 계정이 여러 역할을 가질 수 있음 (프로 댄서이면서 주최자)

**가입 시 온보딩 정보**: 춤 종류 (복수 선택), 종류별 구력 (입문 / 6개월 미만 / 1년 / 3년 / 5년 이상), 리더 · 팔로워 · 둘 다, 거주 도시, 국적 (AI 비자 팁용, 선택 입력), 관심 도시.

## 5. 정보 구조

```
홈
 ├ 상단: 맞춤 추천 (내 춤 종류 × 구력 × 위치 · 관심 도시 × 날짜)
 ├ 1. 이벤트   소셜 / 페스티벌 · 콩그레스 / 워크숍 / 부트캠프
 ├ 2. 수업     퍼블릭 오프라인 (학원 정규반) / 프라이빗 오프라인 (개인 레슨) / 온라인 (2단계)
 ├ 3. 채팅     1:1 담당자 문의 → 2단계 이벤트 그룹챗
 └ 마이        프로필, 저장, 리뷰, (프로) 레슨 관리, (주최자) 이벤트 관리
```

## 6. 기능 요구사항

### 6.1 이벤트 탐색 (MVP 핵심)

* 필터: **도시 · 지도 반경**, **기간 (날짜 범위)**, 춤 종류, 이벤트 유형, 가격, 수준
* 뷰: 리스트, 캘린더, 지도
* 상세: 일시, 장소 (지도), 가격, 라인업 · DJ, 춤 비율 (예: 살사 50 / 바차타 40 / 키좀바 10), 원본 출처 링크, 주최자, 리뷰, 담당자 문의 버튼
* 출처 표시: "주최자 등록" / "공개 정보 수집 (미확인)" 배지. 수집 이벤트는 주최자가 **소유권 주장 (Claim)** 가능

### 6.2 수업

* 학원: 위치, 정규반 시간표, 수준, 가격, 리뷰
* 프라이빗 레슨: 프로 댄서 프로필, 가능 도시 · 기간 (투어 중인 강사 포함), 가격대, 인스타 연결
* 온라인 수업 (2단계): 라이브 · VOD, 결제, 플랫폼 수수료

### 6.3 AI 여행 팁 (소셜 · 페스티벌 상세 페이지)

사용자 국적과 이벤트 장소를 기준으로 생성합니다.

| 항목 | 데이터 출처 (권장) | 주의 |
|:--|:--|:--|
| 비자 · 입국 | 정부 공식 사이트, 유료 API (IATA Timatic, Sherpa 등) | AI 생성만으로는 오류 위험. 반드시 공식 링크 + 면책 문구 |
| 장소 주변 치안 | 각국 외교부 여행경보 (한국 외교부, 미 국무부 등), 리뷰 요약 | 특정 동네 낙인 표현 금지 |
| 리뷰 종합 | 자체 리뷰 | 리뷰 5개 미만이면 요약하지 않음 |
| 특이사항 | 리뷰 + 주최자 입력 | 예: "현장 현금만 가능", "드레스코드", "새벽 2시 이후 대중교통 없음" |

### 6.4 리뷰

* 참여자만 작성 (2단계 결제 연동 후 "참석 확인" 배지, MVP는 이벤트 종료 후 누구나 + 신고 기능)
* 별점 1~5 + 한마디 (최대 140자) + 선택 태그 (음악, 플로어, 수준, 분위기, 가성비)
* 주최자 답글 가능, 리뷰는 주최자 프로필에 누적

### 6.5 채팅

* MVP: 이벤트 · 레슨 상세에서 담당자에게 1:1 문의
* 2단계: 이벤트 그룹챗 (참가자끼리 숙소 · 택시 쉐어, 파트너 찾기)
* 직접 구현하지 말고 Stream, Sendbird 같은 SaaS 사용 권장 (신고 · 차단 · 스팸 필터 포함)

### 6.6 맞춤 추천

* 1차: 규칙 기반 점수 = 춤 종류 일치 × 구력 적합도 × 거리 · 관심 도시 × 날짜 근접도 × 리뷰 점수
* 2차: 저장 · 클릭 · 참석 데이터 쌓인 후 협업 필터링

## 7. 데이터 수집 전략 (가장 중요한 리스크)

"인스타 스크래핑에 의존"은 **핵심 공급원으로 삼으면 안 됩니다.** 이유와 대안은 다음과 같습니다.

| 출처 | 가능 여부 | 판단 |
|:--|:--|:--|
| 인스타그램 스크래핑 | 기술적으로 가능하나 로그인 차단, IP 차단이 잦고 약관 위반 소지. 2024년 Meta v. Bright Data 판결은 "로그아웃 상태 공개 데이터" 한정, 최종 판결 아님 | 보조 수단만. 이미지 · 캡션 재게시는 저작권 문제 |
| Instagram 공식 API | 본인이 연결한 비즈니스 · 크리에이터 계정 데이터만 | **주최자 · 프로가 직접 연결하면 게시물을 이벤트로 자동 변환** (합법 경로) |
| Meetup | 공식 API는 Pro 구독자 중심 | 라틴댄스 데이터량 적음, 우선순위 낮음 |
| Facebook 이벤트 | 2018년 이후 공개 API 사실상 폐쇄 | 링크 붙여넣기 방식만 |
| 페스티벌 공식 웹사이트, 기존 디렉터리 | 공개 웹, 구조화 쉬움 | **MVP 1순위.** robots.txt 준수, 사실 정보 (일시 · 장소)만 저장, 원본 링크 표기 |
| 사용자 · 주최자 제보 | 링크나 포스터 이미지 붙여넣기 → LLM이 일시 · 장소 · 가격 추출 → 사람 검수 | **가장 확장성 높은 경로** |

권장 파이프라인: `수집 (웹 · 제보 · 공식 API) → LLM 구조화 추출 → 중복 제거 (장소 + 일시 + 이름 유사도) → 검수 대기열 → 공개 → 주최자 Claim`

## 8. 수익 모델

"광고 수익이 핵심"은 **초기에는 성립하지 않습니다.** 니치 커뮤니티의 디스플레이 광고 단가로는 월 수십만 방문 전까지 서버비 수준입니다. 권장 순서는 다음과 같습니다.

| 단계 | 수익원 | 이유 |
|:--|:--|:--|
| 1 | 주최자 · 학원 **유료 상단 노출 (Featured)**, 도시별 스폰서 | 구매자가 명확하고 라틴댄스 업계와 직접 연관된 광고 = 단가 높음 |
| 1 | 페스티벌 직접 광고 (배너, 뉴스레터) | 페스티벌은 원래 해외 홍보비를 씀 |
| 2 | 티켓 · 레슨 예약 결제 수수료 (예: 5~10%) | 실제 핵심 수익. Stripe Connect 류 마켓플레이스 결제 |
| 3 | 온라인 수업 수수료 (예: 15~30%), 주최자 SaaS 구독 (참가자 관리) | |
| 보조 | 일반 디스플레이 광고 (AdSense 등) | 트래픽 생기면 덤 |

## 9. 단계별 로드맵

| 단계 | 기간 (예상) | 범위 | 성공 지표 |
|:--|:--|:--|:--|
| MVP (웹) | 6~8주 | 이벤트 탐색 (장소 · 기간 · 지도), 페스티벌 DB, 학원 목록, Google 로그인, 3가지 회원, 주최자 인증 및 이벤트 등록, 리뷰, 1:1 문의, 맞춤 추천 v1 | **서울 + 3개 도시**에서 주간 이벤트 커버리지 80% 이상 |
| 2단계 | +2~3개월 | PWA 또는 앱, AI 여행 팁, 그룹챗, Instagram 연동 자동 등록, Featured 광고 판매 | 주간 활성 사용자, 주최자 등록 이벤트 비율 50% 이상 |
| 3단계 | +3~6개월 | 결제 · 예약, 참석 인증 리뷰, 온라인 수업, 수수료 | 결제 전환율, 거래액 |

**MVP 범위 원칙**: "전 세계"로 시작하면 모든 도시가 비어 보입니다. **한두 개 도시를 완벽하게 채우고 페스티벌만 글로벌로** 시작하는 것이 정석입니다 (Meetup, Yelp도 도시 단위로 확장).

**결론**: "라틴댄스 이벤트 찾기 앱"은 이미 레드오션입니다 (최근 2년 사이 iOS에만 10개 이상 출시). 대부분 실패 원인은 기능이 아니라 **데이터 밀도 부족**입니다. 차별화 지점은 다음 세 가지로 좁히는 것을 권장합니다.

1. **여행자 관점**: 국적 기반 비자 · 치안 · 결제 팁 + 기간 검색 (경쟁 서비스에 없음)
2. **아시아 (한국 · 일본 · 대만 · 동남아) 데이터 밀도**: 유럽 · 남미 앱들의 공백 지역
3. **강사 · 주최자 공급 측 도구**: 인스타 게시물 → 이벤트 자동 변환으로 등록 비용 0에 수렴
